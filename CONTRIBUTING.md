# Contributing

Read [`docs/roster-audit.md`](docs/roster-audit.md) before anything else. It documents how this project's first draft acquired eight fabricated offenders and one defamatory entry, and everything below follows from it.

## Before you open a pull request

1. The subject must already be on [`index/roster.csv`](index/roster.csv). If not, open an issue proposing the addition with sources — do not add a profile and a roster entry in the same PR.
2. Read [`ETHICS.md`](ETHICS.md). It is binding, not advisory.
3. Run `python3 scripts/validate.py` locally. CI runs it too; failures do not merge.

## The rule that matters

**Every claim carries its own source, or it carries `null`.**

```json
{
  "value": null,
  "confidence": "unverified",
  "sources": [],
  "notes": "Searched Utah trial record and Sullivan (2009); no instrument, administrator or date located for any IQ figure."
}
```

A `null` with an honest note is a **contribution**, not a gap. It tells the next contributor exactly what was already tried. A confident value with no source is worse than nothing, because someone downstream will believe it.

Do not fill a field because it looks empty.

## Source admissibility

| Tier | What counts |
|---|---|
| 1 | Court filings, trial transcripts, appellate opinions, official investigative reports, government statistics, coroner and inquest records |
| 2 | Peer-reviewed academic literature |
| 3 | Book-length journalism with footnotes or a documented sourcing apparatus |
| 4 | Contemporaneous news reporting from an established outlet |

**Never admissible, at any tier:**

- Films, television series, docudramas, dramatised reconstructions
- Podcasts and video essays without published sourcing
- Wikis of any kind, including Wikipedia and Murderpedia
- Content generated by a language model
- Aggregator sites that do not cite their own sources

Wikipedia is often a useful **finding aid**. Follow its references, read them, and cite those. Do not cite the article.

**On dramatisations specifically:** the inherited Larry Hall profile drew substantially from the television series *Black Bird* — the carved wooden falcons marking grave sites, the emotional arc of the informant operation — presented as documented fact. Dramatisations invent, compress and reorder by design. The validator rejects them by pattern. Do not work around it.

## Using AI assistance

You may use a language model to draft, translate or restructure. You must:

1. Set `provenance.ai_assisted: true`. This is a disclosure requirement, not a stigma.
2. **Verify every factual claim against a human-readable source you have actually opened.** Not a source the model cited — a source you retrieved and read.

A model will produce a plausible citation for a claim it invented. It will produce a plausible offender for a country you asked about. It will produce "Dodge Falcon" — a vehicle that does not exist — in the middle of an otherwise accurate paragraph. Fluency is uniform across true and false output; you cannot detect fabrication by reading.

If you cannot open the source, the claim does not go in.

## Confidence levels

| Level | Requirement |
|---|---|
| `established` | Two or more **independent** sources, at least one tier 1 or 2 |
| `reported` | One credible source |
| `contested` | Sources disagree. `notes` must state what the disagreement is |
| `unverified` | No admissible source. `value` must be `null`, `notes` must record what was searched |

Two books that both cite the same trial are not independent. Two outlets running the same wire copy are not independent.

Prefer `reported` over `established` when in doubt. Under-claiming costs nothing; over-claiming costs the project its credibility.

## Victim counts

Three fields, never interchangeable, never summed:

- `confirmed_victim_count` — established by conviction or official confirmation
- `attributed_victim_count` — attributed by a **named agency** with a stated methodology
- `claimed_victim_count` — claimed by the offender

If a figure appears in the press with no agency and no methodology, it belongs in `estimate_provenance` as a description of where the number came from, not in any count field.

## Behavioural coding

Coding — commuter/marauder classification, victim-selection description — is interpretation, not fact. Say so in `notes`, name the framework you applied, and cite it. Two contributors coding the same case differently is a finding worth recording, not an error to resolve silently.

## Review

Every PR is reviewed for:

- **Source admissibility** — every citation checked against the tier table
- **Traceability** — a spot-check of at least three claims followed back to the cited source
- **Ethics compliance** — no graphic victim detail, no named survivors, no third-party profiling
- **Confidence calibration** — `established` claims genuinely have two independent sources
- **Category fit** — the case meets [`docs/inclusion-criteria.md`](docs/inclusion-criteria.md)

A PR that adds a well-sourced `null` where a previous contributor put an unsourced value is a good PR and will be merged.

## What gets rejected

- Any claim traceable to a dramatisation
- Any unsourced value, however widely believed
- Graphic victim detail
- Named surviving victims
- Behavioural profiles for unconvicted subjects
- Language treating offenders as skilled, brilliant, or elite
- Bulk additions of many profiles at once — these cannot be meaningfully reviewed

## Reporting an error

Open an issue with the file, the field, and the reason. Errors of the kind documented in the roster audit are expected to surface for some time. **Finding one is a contribution.** There is no embarrassment in a correction and no credit in defending a claim you cannot source.
