# Open Profiling Dataset

A structured, source-traceable dataset of adjudicated serial homicide cases, built for criminological and computational research.

**Status:** `v0.1.0-alpha` — schema stable, 2 of 156 offender profiles populated, 1 case record. Not yet suitable for analysis.

---

## What this is

Every substantive claim in this dataset carries its own citation and its own confidence level. A field either has a source, or it has `value: null` and a note saying what was searched and not found. There is no third option, and the validator enforces it.

That constraint is the whole point of the project. It exists because of what happened to the first draft.

## Why the constraint exists

This dataset began as a 200-subject list assembled with the help of a language model. On review, roughly **20% of the entries were defective**:

- **eight fabricated offenders** — names that correspond to no documented person. One was assembled from a French zoologist and a Second Empire prefect of police. One appeared twice, under two different epithets.
- **one real, living, non-violent person** — a South African woman convicted of falsifying academic qualifications, listed as a serial killer. Publishing that name would have been defamatory and trivially discoverable.
- **one exonerated man** — Sture Bergwall, whose convictions were all overturned, listed as an offender.
- **nine duplicates**, several under different countries, which would have double-counted in any aggregate.
- **twelve category errors** — bombers, spree killers, single-murder cases and one man who never killed anyone at all.

None of this was visible from reading the list. Every entry was formatted identically and read plausibly. That is the failure mode: **an LLM's fluency is uniform across its true and false outputs**, so fabrications inherit the credibility of the facts beside them.

The full audit is in [`docs/roster-audit.md`](docs/roster-audit.md), including the defects found in the three narrative profiles that had already been drafted — among them a vehicle model that does not exist, a conviction that was for kidnapping rather than murder, and a forensic technique described as mathematically conclusive that has since been formally discredited.

A dataset is not judged by its best entries. One fabrication makes the other 199 unusable, because a reader has no way to tell which is which without redoing the verification themselves. Hence the schema.

## How it relates to existing work

The [Radford/FGCU Serial Killer Database](https://scholarscommons.fgcu.edu/esploro/outputs/report/RadfordFGCU-Annual-Report-on-Serial-Killer/99383951932606570) is the established academic reference, covering several thousand offenders with annual published reports. It is broader than this project and should be the first stop for anyone needing offender-level statistics.

This project is narrower and differently shaped. It aims at **depth with traceability**: a smaller set of cases where every claim can be followed back to a court record, a peer-reviewed paper, or a documented investigation, and where contested points are marked as contested rather than resolved by assertion. It is designed for research on *how criminal-justice systems fail and succeed at detection*, not for headcount statistics.

Where the two overlap, Radford/FGCU should be treated as authoritative for identity and chronology.

## Schema

Every claim is an object:

```json
{
  "value": "Commuter",
  "confidence": "reported",
  "sources": [
    {
      "tier": 2,
      "citation": "Canter, David and Paul Larkin. 'The Environmental Range of Serial Rapists.' Journal of Environmental Psychology 13(1), 1993, 63-69."
    }
  ],
  "notes": "Coding is the maintainer's interpretation, not a source-attested fact."
}
```

**Confidence levels**

| Level | Requirement |
|---|---|
| `established` | Two or more independent sources, at least one tier 1 or 2 |
| `reported` | One credible source |
| `contested` | Sources disagree; `notes` must state the disagreement |
| `unverified` | No admissible source. `value` **must** be `null` and `notes` must say what was searched |

**Source tiers**

| Tier | Type |
|---|---|
| 1 | Primary record — court filings, transcripts, official investigative reports, government statistics |
| 2 | Peer-reviewed academic literature |
| 3 | Book-length journalism with a sourcing apparatus |
| 4 | Contemporaneous news reporting |

**Inadmissible at any tier:** dramatisations (film, television, docudrama), unsourced podcasts, wikis, and text generated by a language model. The validator rejects these by pattern. See [`docs/sourcing-policy.md`](docs/sourcing-policy.md).

### Structural safeguards

- **Victim counts are three separate fields.** `confirmed_victim_count` (by conviction), `attributed_victim_count` (by a named agency, with methodology), and `claimed_victim_count` (offender self-report). They are not interchangeable and must never be summed. Offender self-report is recorded as a datum *about the offender's statements*, never as a victim count.
- **Diagnoses require a clinician.** A diagnostic label must be attributable to a named clinician who examined the subject, in a citable document. Labels applied by journalists and commentators go in `commentary_attributions`, recorded as claims about the discourse rather than about the person.
- **Discredited forensics are flagged.** `method_now_disputed` records where a conviction rested on a technique later found unreliable — bite-mark comparison, microscopic hair comparison, arson "indicators" — citing the body that made the finding.
- **No conviction, no profile.** A subject whose `judicial_status` shows charges pending, acquittal or exoneration cannot carry a behavioural profile. The validator blocks it.
- **The Macdonald triad is retained but labelled.** It is coded because the historical literature uses it and replication studies need it. It is **not a predictor** — [Parfitt & Alleyne (2020)](https://pubmed.ncbi.nlm.nih.gov/29631500/) found no support for it as one. The schema says so at the field level.
- **Completed records must state their own limits.** `data_quality.known_gaps` is mandatory for `record_status: complete`.

## Two kinds of record

`dataset/` holds **offender profiles**: subjects with a homicide conviction meeting the criteria in [`docs/inclusion-criteria.md`](docs/inclusion-criteria.md). These are what aggregate statistics are computed from.

`cases/` holds **case records**: subjects excluded from the roster who remain analytically valuable — no homicide conviction, contested confession, exoneration, unidentified offender, or a conviction resting on discredited forensics. A case record documents the **gap between what is publicly claimed and what is judicially established**. That gap is the object of study.

Case records are **never counted in offender aggregates**, and the validator refuses any id that appears in both indexes.

The distinction matters because the alternative corrupts the data. Larry Hall is routinely described as having forty to fifty victims; the record contains one conviction, for kidnapping, with no determinable cause of death. On the roster he would distort every statistic the dataset supports. As a case record he is fully documented — including why the figure has no provenance — and counted in nothing.

A dataset containing only successful prosecutions is also selected on the outcome. `cases/` and [`docs/investigative-failures.md`](docs/investigative-failures.md) are the correction.

## Two files per subject

Each subject has a `.json` and a `.md`. They are not two documents — the Markdown is **compiled from** the JSON by `scripts/render_md.py`.

This is deliberate. A hand-written companion report drifts: it accumulates claims the structured data does not support, sources that were never checked, and confident prose in fields the JSON marks as unestablished. Generating it makes that impossible. The report can only say what the validated data says, and every claim in it carries the same confidence level and the same citations.

**Never edit a `.md` in `dataset/`.** Change the JSON, re-render, commit both. CI fails if they diverge.

## Usage

```bash
pip install jsonschema

python3 scripts/validate.py           # both schemas + sourcing rules
python3 scripts/normalise_sources.py  # canonicalise citations
python3 scripts/render_md.py          # regenerate the Markdown reports
python3 scripts/build_index.py        # regenerate index files
```

CI runs all four on every pull request. It fails if a profile breaks the sourcing rules, if citations are not normalised, if a Markdown report is out of date, or if the index is stale.

## The reference profile

[`dataset/USA-001-BUNDY.json`](dataset/USA-001-BUNDY.json) is the worked example. It is deliberately unimpressive in places: IQ is `null`, blood type is absent entirely, formal diagnoses are `null`, and the attributed victim count is `null`. Each of those fields carries a note explaining what was searched and why nothing was recorded.

The inherited draft filled every one of those fields with a confident number. That is the difference this schema is meant to make.

Note that the reference profile was itself corrected by the validator during construction: birth date and birth place were initially marked `established` on the strength of two tier-3 books, and the tooling correctly refused the claim.
